# ประเด็นและร่างข้อมูลให้ผู้เชี่ยวชาญตรวจ — ยังไม่ใช่สัญญาสำหรับใช้จริง

ฉบับ 8 กันยายน 2569 จัดทำจากสถาปัตยกรรมและโค้ดใน repository เพื่อให้เจ้าของบริการกับผู้รู้กฎหมายกำหนดนโยบาย ไม่ใช่การรับรองว่า Solo Tutor ปฏิบัติตาม PDPA แล้ว ไม่เติมชื่อเจ้าของ ช่องทางติดต่อ หรือระยะเวลาเก็บข้อมูลที่ยังไม่ได้ตกลง

## ข้อเท็จจริงที่ต้องสะท้อนในเอกสาร

| ชุดข้อมูล | ที่อยู่/ผู้เข้าถึง | วัตถุประสงค์ | การลบที่มีในโค้ด |
|---|---|---|---|
| สมุดบัญชี รายชื่อเด็ก ตาราง บิล ใบเสร็จค่าเรียน | localStorage เครื่องครูเป็น plaintext; cloud เป็น ciphertext; กุญแจและไฟล์กู้คืนอยู่กับครู | บริหารการสอน/เรียกเก็บค่าเรียน | ลบรายคนออกจริงได้เฉพาะเมื่อไม่มีประวัติที่ขวางการลบ; หากมี invoice/completion ระบบหยุดเรียนและเก็บประวัติ และปฏิเสธการลบเมื่อมีประวัติส่ง OA การลบเฉพาะรายที่มีประวัติยังต้องกำหนดกระบวนการ/retention; ลบสำเนา cloud แยกได้; บัญชีทั้งฟรีและ paid ลบข้อมูลใช้งานผ่าน API หลังยืนยันตัวตน |
| บัญชีครูและ session | Supabase Auth, token ในเครื่อง | เข้าสู่ระบบและสิทธิ์ใช้บริการ | ลบบัญชีผ่าน API ได้ทั้งฟรี/paid; ประวัติการเงินแยกจาก provider ตาม migration 0009–0010 |
| LINE | ชื่อผู้จ่าย client id, LINE user id, รหัสผูก, ข้อความ/สถานะส่ง, credential OA ที่ seal บนเซิร์ฟเวอร์ | ครูตรวจและส่งข้อความ/รับการตอบกลับ | ยกเลิก OA และคำสั่งหยุดมีขอบเขตต่างกัน ต้องตรวจว่าลบ record ใดและ record ใดยังคงอยู่ |
| คำขอ Pro/ใบเสร็จค่าสมาชิก | Supabase, ครูของบัญชีนั้นและฝ่ายบริการที่มีสิทธิ์ | ให้สิทธิ์แพ็ก ตรวจยอด หลักฐานทางธุรกิจ | เก็บ approved receipt และหลักฐานตรวจโอน/คืนเงินที่จำเป็น แยกจาก provider และลบ note เมื่อบัญชีถูกลบ; ไม่ใช่นโยบายเก็บถาวรที่อนุมัติแล้ว |
| รอสมัคร/ติดต่อ | waitlist: ชื่อ ช่องทางติดต่อ อาชีพ | ติดต่อผู้สนใจตามคำขอ | ไม่มี self-service ที่ผูกกับ auth; ต้องมีคำขอไปยังช่องทางจริงและค้นหาอย่างจำกัด |
| Usage | UUID เครื่องถาวร, event/count/mode; provider_id เฉพาะเมื่อ token ผ่าน Auth | สถิติการใช้งานและผู้จ่ายที่กลับมาใช้ | ลบบัญชีลบ usage ที่ผูกบัญชี; anonymous events ไม่อาจค้นกลับจากบัญชีอย่างแม่นยำ |
| Error | ชนิด error, ตำแหน่ง asset, route template, version/browser | หาข้อผิดพลาด | ไม่ส่งข้อความ exception หรือ ledger จาก client; retention ยังต้องกำหนด |
| Rate limit | hash ที่มี server secret ผสม IP, จำนวนครั้ง/เวลา | กันใช้ทรัพยากรเกิน | cleanup ข้อมูลที่เก่ากว่า 2 ชั่วโมงตาม schedule งานระบบ |
| Backup ฐานข้อมูล | encrypted GitHub artifact และ passphrase ผู้ดูแล | กู้ภัย | artifact ตั้งอายุ 90 วัน; ต้องมีกระบวนการไม่คืนข้อมูลที่ถูกลบเมื่อนำ backup เก่ามา restore |
| ไฟล์ที่ดาวน์โหลด | CSV/ledger backup/recovery key ในเครื่องผู้ใช้ | ย้ายเครื่อง/สำรอง | บริการดึงกลับมาลบไม่ได้ ผู้ถือไฟล์ควบคุมเอง |

Anuphan อยู่บน host ของแอปในรุ่นนี้ ไม่มี request ไป Google Fonts ขณะเปิดแอป การโหลดเว็บยังเปิดเผยข้อมูลเครือข่ายกับ host และการเชื่อม Supabase/LINE/Google Sheets ตามฟีเจอร์ที่ใช้

## รายการที่ต้องตัดสินใจก่อนให้ลงนาม/เผยแพร่

1. ชื่อและสถานะทางกฎหมายของผู้ให้บริการ ที่อยู่และช่องทางรับคำขอที่มีคนตอบได้
2. บทบาทตามแต่ละวัตถุประสงค์: ครูอาจเป็นผู้ควบคุมข้อมูลเด็กที่ครูกำหนดการใช้; Solo Tutor อาจเป็นผู้ประมวลผลตามคำสั่งในส่วนนั้น และเป็นผู้ควบคุมสำหรับบัญชี/ธุรกรรม/สถิติของบริการเอง ห้ามใช้คำว่า “เราเป็นผู้ประมวลผลเท่านั้น” เหมารวม
3. ฐานกฎหมายข้อมูลเด็ก/ผู้ปกครองและรูปแบบแจ้งข้อมูลที่ครูใช้; consent ของผู้เยาว์พิจารณาตามข้อเท็จจริง ไม่กำหนดอายุเดียวแทนทุกกรณี
4. ผู้รับข้อมูล ผู้ประมวลผลช่วงและการโอนข้อมูลข้ามประเทศตาม region/project จริง รวม Supabase, LINE, host, GitHub backup และ Google Sheets เมื่อครูเปิด
5. Retention รายชุด: ระหว่างใช้บริการ หลังยกเลิกแพ็ก/บัญชี การเงิน กฎหมายหรือข้อพิพาท telemetry/error/waitlist/LINE และสำรอง; ระบุ trigger, ระยะเวลา, ผู้อนุมัติข้อยกเว้นและหลักฐานลบ ไม่มีการเพิ่ม cron ลบข้อมูลครูตามอายุที่เดาเอง
6. ตรวจขอบเขตข้อมูลการเงินที่เก็บหลังลบ paid account รวมเลขอ้างอิงธนาคารและป้ายผู้ตรวจ และกำหนดระยะเวลา/กระบวนการลบหรือแก้ไขหลักฐานเมื่อครบกำหนด; ไม่อ้างว่า detached record เป็น anonymous
7. การยืนยันผู้ร้อง สิทธิของผู้ปกครองและส่งต่อไปครูผู้ควบคุม เราอ่าน ciphertext ไม่ได้จึงลบเด็กเฉพาะรายให้ครูไม่ได้โดยตรง แต่ยังต้องมีช่องทางรับและติดตามคำขอ
8. ขั้นตอน incident: จัดประเภท ประเมินความเสี่ยง บันทึกเวลา ผู้ตัดสินใจ และการแจ้งตามข้อกฎหมายที่ใช้ อย่าให้ error log กลายเป็นที่เก็บชื่อเด็ก
9. ยกเลิก/คืนเงิน/ภาระรับผิดและสิทธิผู้บริโภค: ตรวจข้อ “ไม่คืนเงินรอบที่เริ่มใช้แล้ว” และข้อยกเว้นก่อนใช้จริง
10. การรับรองว่าใช้งานฟรี/หมด Pro แล้วยังเข้าถึงและส่งออกอะไรได้บ้าง รวมข้อมูลเกินเพดานและระยะเวลาบน cloud

## โครง DPA สำหรับผู้ร่างสัญญา

- คู่สัญญาและบทบาทแยกตามชุดข้อมูล
- เรื่องและระยะเวลาที่ประมวลผล ลักษณะงาน วัตถุประสงค์ ประเภทบุคคล/ข้อมูล
- คำสั่งครูและขอบเขตที่บริการทำเอง; การเปลี่ยนคำสั่งและการแจ้งคำสั่งที่ขัดกฎหมาย
- การรักษาความลับ สิทธิ์เข้าถึงและมาตรการเทคนิค (client encryption ไม่ครอบคลุม local plaintext หรือ LINE metadata ทั้งหมด)
- ผู้ประมวลผลช่วง ภูมิภาคและกลไกแจ้งเปลี่ยนรายชื่อ
- การช่วยเรื่องสิทธิและเหตุละเมิด ข้อมูลที่อ่านไม่ได้และผู้รับผิดชอบปฏิบัติแทนครู
- ส่งคืน/ลบ/ข้อยกเว้นที่มีกฎหมายรองรับ และการจัดการสำเนาสำรองหลังยุติบริการ
- หลักฐานตรวจสอบ การแจ้งเปลี่ยนมาตรการ การติดต่อและลำดับเอกสารเมื่อขัดกัน

อ้างอิงเพื่อให้ผู้เชี่ยวชาญตรวจ: [PDPA ฉบับราชกิจจานุเบกษา](https://ratchakitcha.soc.go.th/documents/17082307.pdf) โดยเฉพาะมาตรา 6, 20, 23, 33, 37 และ 40 เอกสารนี้ยังไม่มีถ้อยคำสัญญาที่ควรให้ผู้ใช้ยอมรับแทนการตรวจดังกล่าว
