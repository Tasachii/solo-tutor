## 2. หลักการใหม่ (แทนกติกาเดิม "ข้อมูลเดโมห้ามถึงผู้ปกครองจริง")

1. **OA ขึ้นกับ 3 อย่าง: บัญชีครูที่ล็อกอิน + ช่อง OA ที่ active + ผู้ปกครองที่จับคู่ด้วยรหัสของครูคนนั้น — ไม่ขึ้นกับว่าสมุดเป็นเดโมหรือจริง**
2. ข้อความจากเดโมถึงมือถือได้**เฉพาะเครื่องที่ครูที่ล็อกอินอยู่จับคู่เองด้วยรหัสที่ตัวเองสร้าง** (ผู้ปกครองต้องพิมพ์รหัส 6 หลักที่ครูออกให้ในเซสชันนั้น) — จึงไม่มีทางที่ข้อมูลสมมติจะไปโผล่ที่ผู้ปกครองแปลกหน้า
3. ปุ่มทุกปุ่มทำของจริง (กติกาเจ้าของ 9 ก.ย. เช้า ยังอยู่) — หน้า LINE ในเดโมจึงเป็นหน้าเดียวกับโหมดจริง ไม่ใช่คำอธิบาย
4. ลิงก์ที่ออกจากเครื่องต้องเปิดได้จากเครื่องอื่น → เมื่อส่งผ่าน OA (ทั้ง 2 โหมด) เผยแพร่เอกสารเข้ารหัสเหมือนโหมดจริง และ regex กันลิงก์ `#/client|receipt/` ทำงานในเดโมด้วย

## 5. ชุด B — OA กลางของ Solo ("ทุกเมลใช้ได้" ไม่ต้องเปิด LINE Developers) · **รอคำสั่ง**

### 5.1 ทำไมต้องแตะฐาน (ไม่ใช่แค่แอป)
- `line_channels.provider_id` = primary key, `bot_user_id unique` → OA เดียวผูกหลายบัญชีไม่ได้ (`0001_line.sql:37-40`)
- webhook หา provider จาก `destination` (bot id) → channel → provider (`line-webhook/index.ts:53-55`) — OA กลางทำให้ทุก event มาจาก bot เดียว จึงไม่รู้ว่าเป็นครูคนไหนจนกว่าจะอ่านรหัส
- `line_link_codes` primary key `(provider_id, code)` และ `redeem_line_link_code(p_provider_id, …)` (`0001_line.sql:59-66, 165`) → ต้องค้นรหัสแบบ**ทั่วระบบ** (unique index บนรหัสที่ยังไม่ใช้/ยังไม่หมดอายุ)
- `redeem` โยน `recipient not found` ถ้าไม่มีแถว follow (`0001_line.sql:187`) — นี่คือที่มาของกับดัก "บล็อกแล้วแอดใหม่" → OA กลางต้อง upsert recipient ตอน redeem แทน
- โควตา `quota_*` อยู่บนแถว channel (ต่อ OA) และ rate-limit `line_link_attempts(provider_id, line_user_id)` → ต้องเป็น**ต่อครู** (ตารางใหม่) และ attempts key ด้วย line_user_id ล้วน
- ผู้ปกครอง 1 คนเรียนกับครูหลายคนได้ → ข้อความ/สลิปที่ผู้ปกครองส่งกลับ ต้องมีกฎเลือกครู: **ครูที่ส่ง outbox ถึงคนนี้ล่าสุด** และ mirror ให้ครูอื่นที่ผูกอยู่เห็นด้วย
- `line-send` ดึง token ต่อ provider (`line-send/index.ts:99-127`) → ต้องอ่านจากแถว channel กลางแทน

### 5.2 ดีไซน์
| ส่วน | ตอนนี้ | OA กลาง |
|---|---|---|
| ช่อง OA | 1 แถวต่อครู ครูวาง secret/token เอง | 1 แถว "platform" (provider_id = บัญชีระบบ) เก็บ secret/token เข้ารหัสเหมือนเดิม · ครูไม่เห็นฟอร์มนี้ · ครูที่อยากใช้ OA ตัวเอง (แบรนด์ตัวเอง) ยังทำได้ = ตัวเลือก "ใช้ OA ของฉันเอง" (ทางเดิมทั้งก้อน เก็บไว้เป็นของ Pro) |
| รหัสเชื่อม | ต่อครู | ค้นทั่วระบบ 6 หลัก หมดอายุ 24 ชม. ใช้ครั้งเดียว (พื้นที่ 1 ล้าน กับรหัสที่ยังไม่หมดอายุพร้อมกันหลักร้อย ชนกันแทบไม่เกิด และ `issue` วนใหม่อยู่แล้ว) |
| ผู้รับ | `(provider_id, line_user_id)` | เหมือนเดิม — LINE 1 คนมีได้หลายแถว (หลายครู) · redeem upsert แถวให้ครูนั้น |
| โควตา | ต่อ OA 300/เดือน | ตาราง `line_provider_quota(provider_id, month, used, limit)` · Free = N ข้อความ/เดือน (เสนอ 30) · Pro ตามแพ็ก · ค่า LINE plan เป็นต้นทุนของ Solo → เป็นเหตุผลจริงของราคา Pro |
| เสียงข้อความ | ชื่อ OA = ของครู | **ชื่อ OA ที่ผู้ปกครองเห็น = ชื่อ OA กลาง** — เนื้อความยังเป็นเสียงครู (มี "(ครูเต้)" ท้ายบรรทัดพร้อมเพย์แล้ว) ควรเติมบรรทัดแรก "ข้อความจากครูเต้" กันสับสนเมื่อผู้ปกครองมีครูหลายคน |
| ตั้งค่าฝั่งครู | LINE Developers 15–30 นาที | **0 ขั้น** — ล็อกอินแล้วกด "เชิญผู้ปกครอง" ได้เลย |

### 5.3 สิ่งที่เจ้าของต้องตัดสินใจก่อนเริ่ม B
1. **ชื่อ OA ที่ผู้ปกครองทุกคนจะเห็น** — คง "Solo Tutor" (ขัดหลัก "ไม่มีคำว่า Solo ถึงผู้ปกครอง" แต่ตรงไปตรงมา) หรือชื่อกลาง ๆ เช่น "แจ้งค่าเรียน" · เปลี่ยนได้ใน OA Manager ไม่ต้องแตะโค้ด
2. โควตาฟรีต่อครูต่อเดือน และใครจ่ายค่า LINE plan เมื่อเกินโควตาฟรีของ OA
3. OA กลางใช้ `@458gfbxa` เดิม (ผู้ปกครองน้องอิงผูกอยู่แล้ว ย้ายได้ด้วย migration) หรือสร้าง OA ใหม่แยกจากของทีม

### 5.4 ขั้นตอน (ประมาณ 2 วันทำ + ทดสอบมือถือจริง 1 รอบ)
1. migration `0020_platform_line_channel.sql`: แถว channel กลาง · unique index รหัสทั่วระบบ · `redeem_line_link_code_v2(p_line_user_id, p_code)` upsert recipient · `line_provider_quota` · attempts key ใหม่ · ฟังก์ชัน `route_inbound(line_user_id)` · **พิสูจน์บน PG17 local ที่จำลอง schema `extensions` แล้ว** (กับดัก pgcrypto 0019)
2. edge: `line-webhook` (หา channel กลางก่อน ถ้าไม่ใช่ค่อย fallback ต่อครู · redeem v2 · route inbound) · `line-send` (token จากแถวกลาง + หักโควตาต่อครู) · `line-connect` เหลือไว้สำหรับ "ใช้ OA ของฉันเอง"
3. แอป: `useLineLink` ใช้ทางกลางเป็นค่าเริ่มต้น · หน้า LINE OA ไม่มีฟอร์ม secret/token (ย้ายไปใต้ "ขั้นสูง") · ข้อความเชิญใช้ลิงก์แอด OA กลาง
4. เจ้าของ: กด APPLY (workflow เดิม) · วาง secret/token ของ OA กลางครั้งเดียวผ่าน workflow ใหม่ `set-platform-channel` (พิมพ์ SET, ค่าเป็น input แบบ secret ไม่ลง log) · เปลี่ยนชื่อ OA ตาม 5.3
5. ทดสอบ: บัญชีครู 2 บัญชี (KU + อีกเมล) เชิญผู้ปกครองคนเดียวกัน → มือถือได้ 2 ข้อความจาก OA เดียว แยกครูถูก → ส่งสลิปกลับ → โผล่ที่ครูที่ส่งล่าสุด
6. ปล่อยหลังธง `VITE_LINE_PLATFORM=1` — ปิดธง = พฤติกรรมเดิมทั้งหมด
