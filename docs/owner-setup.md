## ข้อ 1 — PromptPay ของทีม (15 นาที) · **ไม่ใช่ตัวขวางการพิทช์**

> เรื่องนี้กระทบ **ปุ่ม "ขอเปิด Pro" อย่างเดียว** คือช่องทางให้ครูโอนค่าสมาชิกมาที่ทีม
> **ไม่กระทบการออกบิลให้ผู้ปกครองเลย** เพราะ QR ที่ผู้ปกครองสแกนคือ **เลขพร้อมเพย์ของครูคนนั้น**
> ซึ่งครูกรอกเองในแอปตอนตั้งค่าครั้งแรก (`Onboarding` ขั้นที่ 1) และแอป**บล็อกการส่งข้อความเรื่องเงิน**
> จนกว่าครูจะกรอกชื่อผู้รับเงินและเลขที่ถูกต้อง (`src/core/messageDelivery.ts`)
> ถ้าเวลาไม่พอ **ข้ามข้อนี้ไปก่อนได้** แล้วบนเวทีอธิบายว่าการเปิด Pro ยังทำผ่านการติดต่อทีม

หน้า "ขอเปิด Pro" จะไม่แสดง QR เลยจนกว่าตัวแปรสองตัวนี้จะมีค่าที่ผ่านการตรวจรูปแบบ

### 1.1 ยืนยันเลขกับ Ing
1. Ing เปิดแอปธนาคาร → PromptPay → ดูว่าผูกกับ **เบอร์โทร** หรือ **เลขบัตรประชาชน** และชื่อบัญชีสะกดยังไง
2. อีกคนสแกน/ใส่เลขในแอปธนาคาร → **ดูชื่อผู้รับบนหน้ายืนยัน** → ตรงแล้วกดยกเลิก · **ไม่ต้องโอน 1 บาท** เพื่อให้ถือว่าผ่าน การโอนทดสอบเป็นการตัดสินใจของเจ้าของ และไม่นับเป็นรายได้
3. Ing ส่งเลข + ชื่อผู้รับให้เต้ (เลข PromptPay เป็นข้อมูลที่ตั้งใจเผยแพร่ ส่งในแชทได้ ไม่ใช่ secret)

### 1.2 ตั้ง Variables ใน GitHub
1. https://github.com/Tasachii/solo-tutor → **Settings** → **Secrets and variables** → **Actions**
2. กดแท็บ **Variables** (ไม่ใช่ Secrets — สองค่านี้แสดงบนเว็บให้ครูเห็น ไม่ใช่ความลับ)
3. **New repository variable** ทีละตัว

| Name | Value | เงื่อนไขที่โค้ดตรวจ (`src/platform/config.ts`) |
|---|---|---|
| `VITE_SOLO_PROMPTPAY` | เบอร์ 10 หลัก เช่น `0812345678` หรือเลขบัตร 13 หลัก | ตัวเลขล้วน ไม่มีขีด ไม่มีเว้นวรรค · ผิดรูปแบบ = ระบบมองว่าว่าง QR ไม่ขึ้น |
| `VITE_PROVIDER_LEGAL_NAME` | ชื่อผู้ให้บริการที่ครูเห็น เช่นชื่อบัญชีที่ปลายทางเห็น | ยาว 2–160 ตัว · **ห้ามมีคำว่า** `example`, `todo`, `xxx` (โค้ดปฏิเสธ) |

### 1.3 Deploy ใหม่
**Actions** → **Verify and deploy** → **Run workflow** → branch `main` → Run
รอ 4–8 นาทีจนเป็นเครื่องหมายถูกเขียว (ค่า Variables เข้าเว็บตอน build เท่านั้น ไม่ deploy ใหม่ = ค่าไม่เข้า)

### 1.4 ตรวจ
1. เปิดเว็บในหน้าต่าง **ไม่ระบุตัวตน** (กัน cache)
2. เข้าสู่ระบบบัญชีครูของทีม (โหมดข้อมูลจริง) → เมนู → บัญชีครู → **ขอเปิด Pro**
3. ต้องเห็น QR + ชื่อผู้รับตรงกับที่ Ing บอก
4. สแกน QR ด้วยแอปธนาคาร → ต้องขึ้นชื่อผู้รับถูกต้อง → **ยกเลิก ไม่ต้องโอน**

**ถ้า QR ไม่ขึ้น**: เช็คว่าอยู่ในแท็บ Variables จริง · ชื่อตัวแปรพิมพ์ใหญ่ทั้งหมด · เลขไม่มีขีด · ชื่อไม่มีคำต้องห้าม แล้ว Run workflow ใหม่

## ข้อ 5 — ยืนยันว่า alert ถึงคนจริง (5 นาที)

> [Uptime run 34219854721](https://github.com/Tasachii/solo-tutor/actions/runs/34219854721) · [ops run 34224331395](https://github.com/Tasachii/solo-tutor/actions/runs/34224331395)

สิ่งที่ **ยังไม่เคยพิสูจน์** คือเมื่อมันล้ม แล้วมีคนได้รับแจ้งจริงหรือเปล่า workflow เขียวไม่ได้แปลว่าเส้นทางแจ้งเตือนทำงาน

1. เปิด GitHub → **Watch** repo แบบ All Activity สำหรับเต้และคนสำรอง เพื่อให้ Issue ป้าย `ops-alert` เข้าอีเมลจริง
2. ตกลงกันว่าใครรับผิดชอบตอบ และภายในกี่ชั่วโมง

4. อยากทดสอบเส้นทางแจ้งเตือนจริง สั่ง AI ให้จำลองความล้มเหลวในสาขาแยกได้ ไม่ต้องรอเจ้าของ

## ข้อ 8 — ตัดสินใจเรื่อง PDPA (หลังพิทช์)

ค่าที่เสนอถูกเติมลงเอกสารแล้ว (`docs/data-inventory.md`, `docs/incident-runbook.md` ข้อ 5) ทำเครื่องหมายว่า **เสนอ:** ทีมแค่ยืนยันหรือแก้

| หัวข้อ | ค่าที่เสนอไว้ |
|---|---|
| ข้อมูลนักเรียน/ผู้ปกครอง | เก็บจนครูลบบัญชี |
| หลักฐานการเงินค่าสมาชิก | 5 ปี (กฎหมายบัญชีไทย) |
| ข้อความ OA + แชทขาเข้า | 12 เดือน |
| ตัวนับการใช้งาน | 24 เดือน |
| error log | 90 วัน |
| waitlist | 12 เดือน หรือจนเปิดบริการ |
| ผู้ถือ `BACKUP_PASSPHRASE` | 2 คน (เต้ + อีก 1) |
| ผู้รับ alert | เต้หลัก · อีก 1 คนสำรอง · ช่องทาง GitHub Issue |
| RTO / RPO | 24 ชม. / 24 ชม. (backup รันรายวันแล้ว) |

**ห้ามให้ครูกดยอมรับเอกสารพวกนี้จนกว่าผู้เชี่ยวชาญกฎหมายจะตรวจ**

> **แก้จากคู่มือเดิม** ที่เลื่อนงาน PDPA ไปหลังพิทช์ทั้งก้อน เลื่อนได้เฉพาะเมื่อยัง**ไม่รับข้อมูลเด็กจริง**
> แยกให้ชัดสองวัน: วันเดโมด้วยข้อมูลสมมติ กับวันเปิดให้ครูกรอกข้อมูลนักเรียนจริง — วันหลังต้องผ่าน gate ก่อน
