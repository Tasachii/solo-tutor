# เปิด Pro ให้ครู (คู่มือทีม)

อัปเดต 8 กันยายน 2569 · ใช้คู่กับ [payment-operations.md](payment-operations.md) ซึ่งเป็นขั้นตอนเต็มพร้อมกติกาหลักฐานและการคืนเงิน

Solo ไม่ถือเงิน — ครูส่งคำขอในแอป (เมนู → บัญชีครู → ขอเปิด Pro) แล้วโอนเข้าพร้อมเพย์ของทีมตามยอดที่แอปแสดง
ทีมเห็นยอดใน**รายการเดินบัญชีจริง** จึงค่อยอนุมัติในฐานข้อมูล แอปของครูเห็นแพ็กใหม่ในรอบซิงก์ถัดไป (เปิดแอปหรือกด "ซิงก์ตอนนี้")

ทำใน Supabase Dashboard → SQL Editor (สิทธิ์ service_role อยู่แล้ว) ห้ามนำ service-role key ออกไปที่อื่น

## 1. ดูคำขอที่รออยู่

```sql
select r.id, u.email, r.months, r.amount, r.note, r.created_at
from public.plan_requests r join auth.users u on u.id = r.provider_id
where r.status = 'pending' order by r.created_at;
```

`amount` คำนวณฝั่งเซิร์ฟเวอร์จาก `months` (1 → 299 · 3 → 799 · 12 → 2,490 — `plan_price()` ใน 0006 มีเทสล็อกให้ตรงกับหน้าเว็บ) ครูแก้ไม่ได้

## 2. เห็นยอดโอนในรายการเดินบัญชีแล้ว → อนุมัติพร้อมหลักฐาน

เทียบชื่อผู้โอน / เวลา / ยอด กับรายการเดินบัญชีจริง ยอดต้องเท่ากับ `amount` พอดี **ห้ามใช้ภาพสลิปอย่างเดียว** และห้ามสร้างเลขอ้างอิงสมมติ

```sql
select * from public.approve_plan_request_verified(
  '<id จากข้อ 1>',
  '<เลขอ้างอิงธุรกรรมจากธนาคาร>',
  299,                                  -- ยอดที่เข้าจริง ต้องเท่ากับ amount ของคำขอ
  '2026-09-10T14:05:00+07:00',          -- เวลาที่รายการเกิดในธนาคาร พร้อมเขตเวลา
  '<ชื่อ/ป้ายผู้ตรวจ เช่น Ing>'
);
```

คืน `evidence_id`, `plan_until` ใหม่ และ `receipt_no` (รูปแบบ `SP-YYYYMM-0001`) — ถ้าครูยัง Pro อยู่ วันจะต่อท้ายจากวันหมดอายุเดิม ไม่นับใหม่จากวันนี้ ครูเห็นใบเสร็จค่าสมาชิกในหน้าบัญชี → ประวัติค่าสมาชิก

ถ้าขั้นใดผิด (ยอดไม่ตรง, เลขอ้างอิงซ้ำ, เวลาอนาคต) ทั้ง transaction จะ rollback คำขอยัง pending

**ห้ามเรียก `approve_plan_request('<id>')` รุ่นเดิม** — ไม่มีหลักฐานธนาคาร รายการจะไปอยู่กลุ่ม `legacy_unverified` และไม่นับใน verified gross/net ที่ใช้พิทช์หรือทำบัญชี

## 3. ยอดไม่ตรง / ไม่ได้โอน

```sql
select public.reject_plan_request('<id>');
```

ครูเห็นสถานะ "ไม่ผ่าน" ในประวัติค่าสมาชิกพร้อมช่องทางติดต่อทีม และส่งคำขอใหม่ได้ (คำขอที่รออยู่ได้ทีละหนึ่ง ครูยกเลิกเองได้จากในแอป)

## 4. คืนเงิน

คืนเงินจริงผ่านธนาคารก่อน แล้วบันทึกด้วย `record_plan_refund(...)` ตามขั้นตอนใน [payment-operations.md](payment-operations.md#คืนเงิน) หลักฐานเป็น append-only แก้ทีหลังไม่ได้

## ดูสถานะแพ็กของครูทุกคน

```sql
select u.email, p.plan, p.plan_until, p.paused_at
from public.providers p join auth.users u on u.id = p.id order by p.plan_until desc nulls last;
```

- `paused_at` ไม่ว่าง = ครูกดพักไว้ วันที่เหลือไม่ถูกนับ กด "ใช้ต่อ" แล้ว `plan_until` เลื่อนออกไปเท่าวันที่พัก (พักได้จนถึงวันสุดท้ายของแพ็ก)
- วันทั้งหมดคิดเป็นวันไทย (`public.thai_today()`) ไม่ใช่ UTC

## ตัวเลขสำหรับพิทช์/บัญชี

รัน [scripts/pitch-metrics.sql](../scripts/pitch-metrics.sql) หรือ [scripts/paid-usage.sql](../scripts/paid-usage.sql) — คอลัมน์ที่ขึ้นต้น `verified` เท่านั้นที่เป็นรายได้ยืนยันแล้ว คอลัมน์ `legacy_unverified` แสดงแยกและห้ามนำเสนอเป็นรายได้

## ยังไม่ได้ตั้ง (ก่อนรับเงินรายการแรก)

- Repository Variables `VITE_SOLO_PROMPTPAY` และ `VITE_PROVIDER_LEGAL_NAME` ยังว่าง → หน้าขอเปิด Pro ปิดอยู่โดยตั้งใจ (`PAID_PLAN_AVAILABLE = false`) ใส่เลขพร้อมเพย์ทีมและชื่อผู้ให้บริการจริง แล้ว rerun **Verify and deploy** QR จะขึ้นพร้อมยอดของแพ็กที่เลือก
- อีเมลแจ้งเตือนเมื่อมีคำขอใหม่ยังไม่มี — `operations.yml` นับคำขอค้างเกิน 24 ชม. เป็นข้อผิดพลาดและเปิด Issue แทน; ตรวจข้อ 1 วันละครั้ง
- มัดจำ 100 บาท (ถ้าทีมใช้) ไม่มี flow ในระบบ ต้องบันทึกแยกนอกระบบ **ห้ามลงเป็นการชำระแพ็ก 299**
