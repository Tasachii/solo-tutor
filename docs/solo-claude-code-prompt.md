# Prompt สำหรับ Claude Code — แก้เว็บ Solo Tutor รอบหลัง validation

> วิธีใช้: เปิด Claude Code ที่โฟลเดอร์ `~/Documents/solo-tutor` แล้ววางทั้งไฟล์นี้เป็น prompt เดียว
> (โฟลเดอร์ยังชื่อเดิมก็ได้ — งานข้อ 0 จะจัดการเรื่องชื่อให้)

---

## บริบท

โปรเจกต์นี้คือ **Solo Tutor** — แอดมิน AI สำหรับติวเตอร์ · ไม่มีชื่อย่อยรายอาชีพ (มติ 6 ก.ย.)
repo `solo-tutor` เป็น Vite + React + TypeScript deploy ขึ้น GitHub Pages ไม่มีหลังบ้าน ไม่มีล็อกอิน ทุกอย่างเป็นเดโมข้อมูลสมมติ

**เพิ่งจบรอบ validation จริงมา** — สัมภาษณ์เชิงลึกติวเตอร์ 8 คน + แบบสอบถาม 50 คน ผลที่ได้เปลี่ยนสมมติฐานเรื่องกลุ่มเป้าหมายและลำดับความสำคัญของฟีเจอร์ งานรอบนี้คือทำให้เว็บพูดตรงกับสิ่งที่ข้อมูลบอก

### หลักการเดิมที่ห้ามละเมิด (อยู่ใน README แล้ว)
1. Solo Tutor ไม่ถือเงินของใคร — QR เป็นของผู้ให้บริการ เงินเข้าบัญชีเขาตรง
2. ตัวเลขทุกตัวมาจาก ledger ไม่มีค่าคงที่ ไม่มี AI คำนวณเงิน
3. AI ร่าง คนกดส่ง — ไม่มีข้อความไหนออกไปโดยผู้ใช้ไม่ได้กดปุ่มส่ง
4. `core/` กับ `app/` ไม่รู้จักอาชีพ — คำเฉพาะอาชีพอยู่ใน `professions/` และ `copy/` เท่านั้น
5. ข้อความถึงลูกค้าเป็นเสียงของผู้ให้บริการ ห้ามมีคำว่า "ระบบ" "อัตโนมัติ" หรือ "Solo"

## 1 · หน้า Landing — เปลี่ยนกลุ่มเป้าหมายและใส่หลักฐานจริง

**สิ่งที่ข้อมูลบอก:** ความเจ็บแปรตามจำนวนนักเรียนจริง แต่**เส้นไม่ได้อยู่ที่ 30 คน** — กลุ่ม 11–30 คนคือกลุ่มที่เจ็บและยอมจ่ายมากที่สุด (เจอคนโอนช้า 76% · ใช้เวลาสิ้นเดือนเกิน 3 ชม. 41% · รับราคา 299 ถึง 71%) ส่วนกลุ่ม 1–10 คนตอบว่า "ยังไม่สนใจ" ถึง 43% และรายใหญ่ 31+ คนหลายรายจ้างแอดมินเป็นคนไปแล้ว

แก้ที่ `src/platform/Landing.tsx` และ `src/copy/index.ts`:

- เปลี่ยนกลุ่มเป้าหมายที่พูดถึงทั้งหน้าเป็น **"ติวเตอร์ที่สอนคนเดียว มีนักเรียน 11–50 คน และยังไม่มีแอดมิน"** (ตอนนี้ยังเล็งกว้างเกินไป)
- เพิ่ม section หลักฐาน 1 บล็อกใต้ hero — การ์ดตัวเลข 3–4 ใบจากข้อมูลจริง:
  - `54%` เดือนล่าสุดมีผู้ปกครองโอนช้าอย่างน้อย 1 คน
  - `41%` ของคนที่เคยเจอคนค้างจ่าย เลือกไม่ทวงตรง ๆ
  - `1 ใน 3` มีค่าเรียนค้างเก็บสะสมอยู่ตอนนี้
  - `42 จาก 50` แจ้งยอดด้วยการพิมพ์ LINE เองทีละคน
  - ใต้บล็อกใส่บรรทัดเล็ก: *"จากแบบสอบถามติวเตอร์ 50 คน และสัมภาษณ์เชิงลึก 8 คน · ก.ย. 2569"*
  - ตัวเลขพวกนี้เป็น**ผลสำรวจ ไม่ใช่ ledger** — เก็บเป็น const ในไฟล์ `src/platform/research.ts` ใหม่ พร้อม comment ว่ามาจากไหน อย่าไปปนกับ selector ที่คิดเงิน
- แก้ `landing.why` ("ทำไมเริ่มที่ติวเตอร์") ให้ข้อ 3 ใช้ตัวเลขจากผลสำรวจจริงแทนช่วง 3–5 ชม. ที่เดาไว้

## 2 · เพิ่ม "ตารางสอน + เลื่อนคลาส" ระดับพื้นฐาน

**สิ่งที่ข้อมูลบอก:** เป็นเรื่องที่ผู้ให้สัมภาษณ์ขอเองบ่อยที่สุดโดยเราไม่ได้ถามนำ — 3 ใน 8 คนพูดถึง ("เกลียดการจัดตารางที่สุด", "จัดตารางใน LINE ใช้เวลา 1–2 สัปดาห์", "ลืมจดเลื่อนคลาสแล้วทำอะไรไม่ได้")

**แกนของ Solo Tutor ยังเป็นเรื่องเงิน** — อันนี้เป็นตัวประกอบ ห้ามทำใหญ่กว่าบิล:

- ในหน้า `Today` เพิ่มแถบ "คาบวันนี้" ที่แตะเพื่อ **เลื่อน** ได้ (เลือกวัน/เวลาใหม่) หรือ **ยกเลิก**
- การเลื่อนต้องบันทึกเป็น event ใน ledger (`session_rescheduled`) ไม่ใช่แค่แก้ตัวเลขในหน้าจอ — และห้ามกระทบยอดบิลจนกว่าคาบนั้นจะถูกเช็คชื่อจริง
- เมื่อเลื่อนแล้ว AI ร่างข้อความแจ้งผู้ปกครองในกล่องรอส่ง (ครูกดส่งเอง ตามหลักการข้อ 3)
- ไม่ต้องทำปฏิทินเต็ม ไม่ต้องทำหน้าตารางว่างออนไลน์ให้ผู้ปกครองจอง — อันนั้นเป็น roadmap

## 3 · หน้า Pricing — จัดลำดับใหม่ตามที่ตลาดตอบ

**สิ่งที่ข้อมูลบอก:** 56% บอกว่า 299 บาท/เดือน "พอดี" หรือ "ถูก" · ผู้ให้สัมภาษณ์ระบุเพดานเอง 200–500 บาท/เดือน · คนที่บอกว่าแพงคือกลุ่มนักเรียนน้อย ซึ่งไม่ใช่กลุ่มเป้าหมายเราอยู่แล้ว

- ทำให้ Pro 299 เป็นตัวเลือกที่เด่นชัดที่สุด (badge "คนส่วนใหญ่เลือกอันนี้")
- ใต้ราคาใส่บรรทัด: *"จ่ายเฉพาะเดือนที่ส่งบิล"* ให้เห็นชัด — เป็นจุดที่ลดความกลัวของคนที่สอนไม่สม่ำเสมอ
- เพิ่มบรรทัดเทียบให้เห็นภาพ: *"ถูกกว่าค่าจ้างแอดมิน 1 วัน"*
- คง Free / ไตรมาส 850 / Concierge 1,500 ไว้เหมือนเดิม ไม่ต้องเพิ่มเทียร์ใหม่

## 4 · บิลใน LINE ต้องเป็นพระเอกของหน้าเดโม

**สิ่งที่ข้อมูลบอก:** "ส่งบิลเข้า LINE ผู้ปกครองพร้อม QR" คือฟีเจอร์อันดับ 1 ที่คนเลือก (14 จาก 50) และผู้ให้สัมภาษณ์ย้ำว่า**ผู้ปกครองเข้าแอปหรือกดลิงก์ยาก**

- ใน `ClientPreview` ทำให้หน้าตาเหมือนข้อความ LINE จริงมากขึ้น — ฟองแชท ชื่อครู QR PromptPay อยู่ในข้อความเลย
- ต้องเห็นชัดว่า**ผู้ปกครองไม่ต้องโหลดอะไร ไม่ต้องสมัครอะไร** — เพิ่มบรรทัดนี้ในหน้า Landing ด้วย
- ปุ่ม "ดูมุมมองผู้ปกครอง" ต้องหาเจอง่ายกว่านี้ (ตอนนี้ซ่อนอยู่ในเมนู) — ย้ายมาเป็นปุ่มรองในหน้า Today หรือหลังส่งบิลสำเร็จ

## 5 · เพิ่ม "สรุปพัฒนาการนักเรียน" เป็น roadmap ที่มองเห็นได้

**สิ่งที่ข้อมูลบอก:** มาเป็นอันดับ 2 ของฟีเจอร์ที่คนอยากได้ (12 จาก 50) ซึ่งเราไม่เคยคิดว่าจะแรงขนาดนี้

- **ยังไม่ต้องสร้างฟีเจอร์จริง** — ใส่เป็นการ์ด "เร็ว ๆ นี้" ในหน้า Landing หรือหน้า Pricing พร้อมปุ่มลงชื่อรอ (ใช้ `WaitlistSheet` ที่มีอยู่แล้ว)
- เก็บการกดลงชื่อลง event log เพื่อวัดว่ามีคนอยากได้จริงกี่คน — นี่คือ validation รอบถัดไปที่ไม่ต้องเขียนโค้ดฟีเจอร์เลย

## 6 · Pitch mode — ใส่ผลจริงลงไป

หน้า `Pitch.tsx` ยังเล่าด้วยสมมติฐานเก่า อัปเดตเป็น:
- Problem → Insight → Solution → หลักฐาน โดย**หลักฐานคือตัวเลข 50 คน + 8 บทสัมภาษณ์**
- ใส่คำพูดจริง 2 ประโยคเป็น quote: *"ถ้าเราส่งทวงเงินเอง กลัวผู้ปกครองไม่พอใจ"* และ *"ผู้ปกครองเข้าถึงแอปหรือลิงก์ได้ยาก"*
- ระบุ verdict ให้ตรง: สมมติฐานเดิม "30+ คน" ถูก**ปรับเป็น 11–50 คนที่ยังไม่มีแอดมิน** (validated with adjustment)

## ข้อกำหนดงาน

- ทุก string ใหม่ต้องอยู่ใน `src/copy/` เท่านั้น ห้ามพิมพ์ string ในคอมโพเนนต์
- คำเฉพาะอาชีพต้องมาจาก `professions/` — `core/` และ `app/` ต้องไม่รู้จักคำว่า "นักเรียน" หรือ "ผู้ปกครอง"
- ทุกฟีเจอร์ใหม่ต้องมี unit test และต้องไม่ทำให้ 22 tests เดิมพัง
- อัปเดต e2e ให้ครอบคลุมการเลื่อนคลาสด้วย
- `npm run build && npm run test && npm run e2e` ต้องผ่านก่อน commit
- commit แยกเป็นก้อนตามหัวข้อ 1–6 ข้างบน อย่ารวมเป็น commit เดียว
- ห้ามเปลี่ยนชื่อ repo, ห้ามแก้ `base` ใน vite.config.ts อีก
