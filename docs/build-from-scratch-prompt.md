# Prompt สร้าง Solo Tutor ตั้งแต่ศูนย์

> ไฟล์นี้ตั้งใจให้ **copy ไปวางใน AI ตัวไหนก็ได้** (Claude, v0, Lovable, Bolt, Cursor ฯลฯ)
> เป็น spec แบบสมบูรณ์ในตัวเอง — ไม่ต้องมี repo เดิม ไม่ต้องมีบริบทอื่น
> ตัดออกไป 1 บล็อกนี้ก่อนวางก็ได้ ที่เหลือคือ prompt ทั้งหมด

---

สร้างเว็บแอปชื่อ **Solo Tutor** — ผู้ช่วยงานหลังบ้านสำหรับติวเตอร์สอนพิเศษ

ทำเป็น **static web app** ไม่มีหลังบ้าน ไม่มีล็อกอิน ข้อมูลเก็บใน localStorage ทั้งหมด ต้องเปิดบนมือถือแล้วใช้งานได้จริงเหมือนแอป (PWA — ติดตั้งลงหน้าโฮมได้)

Stack: **Vite + React + TypeScript + react-router (HashRouter)** · CSS ธรรมดา ไม่ต้องใช้ UI framework · ห้ามใส่ dependency เกินจำเป็น

---

## 1. ปัญหาที่แอปนี้แก้

ติวเตอร์ที่สอนคนเดียวมีนักเรียน 11–50 คน จดว่าใครมาเรียนครั้งไหนกระจัดกระจาย (สมุด โน้ตมือถือ แชท LINE) พอสิ้นเดือนต้องนั่งไล่นับ คิดเงิน พิมพ์แจ้งยอดใน LINE ทีละคน แล้วตามคนที่ยังไม่จ่าย — เสียเวลาหลายชั่วโมงทุกเดือน และหลายคนไม่กล้าทวงเพราะกลัวเสียความสัมพันธ์กับผู้ปกครอง

แอปนี้ทำให้เหลือแค่ **แตะยืนยันว่าสอนเสร็จ** ที่เหลือระบบคิดและร่างข้อความให้

## 2. หลักการที่ห้ามละเมิด

1. **ไม่ถือเงินของใคร** — แสดง QR PromptPay ของผู้ใช้เอง เงินเข้าบัญชีเขาโดยตรง แอปไม่แตะเงิน ไม่มีระบบชำระเงินในแอป
2. **ตัวเลขทุกตัวมาจาก ledger** — ยอดเงินทุกยอดคำนวณจากบันทึกการสอนจริง ห้ามมีค่าคงที่ ห้ามให้ AI คิดเงิน
3. **AI ร่าง คนกดส่ง** — ไม่มีข้อความไหนออกไปหาลูกค้าโดยผู้ใช้ไม่ได้กดปุ่มส่งเอง
4. **แกนกลางไม่รู้จักอาชีพ** — logic การคิดเงิน/ledger ต้องไม่มีคำว่า "นักเรียน" หรือ "ผู้ปกครอง" ฝังอยู่ · คำเฉพาะอาชีพอยู่ในไฟล์แยก (ดูข้อ 7)
5. **ข้อความถึงลูกค้าเป็นเสียงของผู้ใช้** — ห้ามมีคำว่า "ระบบ" "อัตโนมัติ" หรือชื่อแบรนด์ในข้อความที่ส่งหาลูกค้า (ยกเว้นบรรทัดเล็กท้ายใบเสร็จ)
6. **ลูกค้าปลายทางไม่ต้องติดตั้งอะไร** — ผู้ปกครองรับบิลเป็นข้อความ LINE ธรรมดา ไม่ต้องโหลดแอป ไม่ต้องสมัคร ไม่ต้องล็อกอิน

## 3. Data model

```ts
type ISODate = string          // 'YYYY-MM-DD'
type Money = number            // บาท จำนวนเต็ม

type BillingMode =
  | { mode: 'per_unit';     rate: Money }                    // จ่ายรายครั้ง
  | { mode: 'flat_monthly'; amount: Money }                  // เหมาเดือน
  | { mode: 'package';      total: number; price: Money; purchasedAt: ISODate }  // แพ็กจ่ายล่วงหน้า

interface Client  { id: string; name: string; lineId?: string; phone?: string }   // ผู้จ่าย = ผู้ปกครอง
interface Subject { id: string; name: string; clientId: string; billing: BillingMode; active: boolean; createdAt: ISODate }  // ผู้เรียน
interface ServiceUnit    { id: string; subjectId: string; scheduledAt: ISODate; time: string; durationMin: number; adHoc?: boolean }  // คาบเรียน
interface CompletionEvent{ unitId: string; completedAt: ISODate; note?: string }  // การยืนยันว่าสอนแล้ว

interface InvoiceLine { description: string; qty: number; unitPrice: Money; amount: Money }
interface Invoice {
  id: string; clientId: string; subjectId: string; period: string   // 'YYYY-MM'
  kind: 'monthly' | 'package'; lines: InvoiceLine[]; total: Money
  status: 'draft' | 'sent' | 'paid' | 'overdue'
  createdAt: ISODate; sentAt?: ISODate; dueAt?: ISODate
}
interface Payment { id: string; invoiceId: string; amount: Money; paidAt: ISODate; slipVerified: boolean; slipAmount?: Money }
interface Receipt { id: string; paymentId: string; number: string; issuedAt: ISODate }

type MessageKind = 'invoice' | 'reminder' | 'renewal' | 'renewal_exhausted' | 'receipt' | 'faq_reply'
interface Message {
  id: string; clientId: string; subjectId?: string; kind: MessageKind
  draft: string; edited?: boolean
  status: 'draft' | 'sent' | 'skipped'
  createdAt: ISODate; sentAt?: ISODate
  dedupeKey: string          // กันร่างซ้ำใบเดิม
}
interface ChatTurn { id: string; clientId: string; from: 'client' | 'provider'; text: string; at: ISODate }

interface AppState {
  provider: { name: string; promptpayId: string }
  today: ISODate                                  // ล็อกวันได้ เพื่อเดโม
  clients: Client[]; subjects: Subject[]; units: ServiceUnit[]; completions: CompletionEvent[]
  invoices: Invoice[]; payments: Payment[]; receipts: Receipt[]
  messages: Message[]; chats: ChatTurn[]
  counters: { receipt: number; invoice: number }
  onboarded: boolean
}
```

state ทั้งก้อนอยู่ใน `useReducer` + persist ลง localStorage ทุกครั้งที่เปลี่ยน

## 4. กฎการคิดเงิน

- **รายครั้ง** — ยอดเดือนนี้ = จำนวนครั้งที่ยืนยันแล้วในเดือนนั้น × rate
- **เหมาเดือน** — ยอดคงที่ ไม่ขึ้นกับจำนวนครั้ง แต่ยังต้องแสดงว่าเรียนไปกี่ครั้ง
- **แพ็ก** — จ่ายล่วงหน้า N ครั้ง · นับครั้งที่ใช้ไปจาก completions · เหลือ ≤ 2 ครั้งให้เตือนต่อแพ็ก · ถ้าใช้เกินโควตาแล้วยังมาเรียน ต้องจับได้และแจ้ง ("วันนี้เป็นครั้งที่ 2 นอกแพ็ก")
- **ปิดเดือน** — ผู้ใช้กดปิดยอดสิ้นเดือน ระบบสร้าง Invoice จาก completions ของเดือนนั้น หลังปิดแล้วแก้ไม่ได้
- **ครบกำหนดชำระ** — ตั้งค่าเริ่มต้น 3 วันหลังส่งบิล · เลยกำหนดให้เปลี่ยนสถานะเป็น overdue
- **บันไดทวง 3 ระดับ** ตามจำนวนวันที่เลย: `soft` (สุภาพมาก) → `clear` (ระบุจำนวนวัน ขอวันชำระ) → `final` (เปิดทางให้คุย ไม่กดดัน)

### ฝั่งผู้ใช้ (ติวเตอร์) — bottom tab 4 แท็บ

| **วันนี้** | การ์ดคาบของวันนี้ ปุ่มยืนยัน "สอนเสร็จ" ใหญ่ กดง่ายด้วยนิ้วโป้ง · ยกเลิกการยืนยันได้ · เพิ่มคาบนอกตาราง · เลื่อน/งดคาบแล้วร่างข้อความแจ้งอัตโนมัติ · แสดง progress ของวัน (ยืนยันแล้ว 3/5) |

| **บิล** | ตัวเลขสรุปบนสุด 4 ตัว (ควรได้ · ได้แล้ว · ค้าง · ทวงกลับมาได้) · รายการบิลจัดกลุ่มตามสถานะ · ปุ่มปิดเดือน · แนบสลิป · ออกใบเสร็จ · export CSV |
| **แอดมิน** | กล่องข้อความรอส่ง — แสดงข้อความที่ระบบร่างไว้ ผู้ใช้อ่าน แก้ inline ได้ แล้วกดส่งทีละใบหรือทั้งคิว · อีกแท็บเป็นแชทจำลองคำถามลูกค้า + คำตอบที่ระบบร่างให้ |

### หน้าอื่น
- **Landing** — หน้าขาย อธิบายว่าแอปทำอะไร มีปุ่มลองเดโม
- **ราคา** — Free (เช็คชื่อ นับครั้ง export) / Pro 299 บาทต่อเดือน (บิล LINE, ตรวจสลิป, ใบเสร็จ, ทวงแทน, dashboard) / แพ็ก 3 เดือน 799 / 12 เดือน 2,490
- **Onboarding** — 3 ขั้น ข้ามได้ทุกขั้น: ชื่อผู้ใช้ → เลข PromptPay → วางรายชื่อผู้เรียน
- **หน้าบิลฝั่งลูกค้า** — เปิดจากลิงก์ในแชท ไม่ต้องล็อกอิน แสดงชื่อผู้เรียน จำนวนครั้ง ยอดเงิน QR PromptPay และประวัติย้อนหลัง
- **หน้าใบเสร็จ** — พิมพ์ได้ ดูเป็นทางการ

## 6. การส่งข้อความ (สำคัญที่สุด)

แอปนี้**ไม่ส่งข้อความเอง** และ**ไม่ต่อ LINE API** — ทำแบบนี้แทน:

1. ระบบร่างข้อความเก็บไว้ในกล่องรอส่ง
2. ผู้ใช้กด "ส่ง" → เปิด LINE ด้วย `https://line.me/R/share?text={ข้อความที่ encode แล้ว}`
3. LINE เด้งขึ้นมาพร้อมข้อความกรอกไว้แล้ว ผู้ใช้เลือกแชทของลูกค้าแล้วแตะส่ง
4. กลับมาที่แอป ถามว่า "ส่งแล้วใช่ไหม" → กดยืนยัน → เปลี่ยนสถานะเป็น sent แล้วเด้งข้อความถัดไปในคิวทันที
5. ถ้า popup ถูกบล็อก (มักเป็นบนเดสก์ท็อป) ให้ fallback เป็นคัดลอกข้อความลง clipboard พร้อมแจ้งผู้ใช้

**ข้อความที่ขอเงินต้องมี ยอด + เลข PromptPay + ชื่อผู้รับ เป็นตัวหนังสือในตัวข้อความเสมอ** ลิงก์เป็นแค่ทางเลือกให้ดูรายละเอียด ห้ามเป็นทางเดียวที่จะจ่ายได้ — เพราะลูกค้าปลายทางส่วนใหญ่ไม่กดลิงก์

### โทนข้อความ
สุภาพ อบอุ่น เป็นภาษาคน ไม่ใช่ภาษาระบบ · มีอนุภาคลงท้ายที่สลับได้ตามเพศผู้ใช้ (ครับ/ค่ะ) · ใส่ 🙏 ได้พอประมาณ

ตัวอย่างที่ต้องทำให้ได้ระดับนี้:

> เรียนคุณสมชาย 🙏 ขอแจ้งค่าเรียนคณิตศาสตร์ เดือนกันยายน รวม 8 ครั้ง เป็นเงิน 3,200 บาทครับ
> โอนได้ที่พร้อมเพย์ 08x-xxx-xxxx ชื่อบัญชี ครูพลอย เมื่อโอนแล้วรบกวนส่งสลิปในแชทนี้ได้เลยครับ ขอบคุณครับ

ทวงระดับ soft:
> เรียนคุณสมชาย ขออนุญาตเรียนแจ้งค่าเรียนคณิตศาสตร์ เดือนกันยายน 3,200 บาท ที่ยังไม่ได้รับยอดครับ หากโอนแล้วรบกวนส่งสลิปให้ด้วยนะครับ ขอบคุณครับ 🙏

ทวงระดับ final (ห้ามกดดัน ต้องเปิดทางให้คุย):
> เรียนคุณสมชาย ขออนุญาตเรียนแจ้งเรื่องค่าเรียนคณิตศาสตร์ เดือนกันยายน 3,200 บาท อีกครั้งครับ หากมีเรื่องการชำระที่อยากปรึกษา ทักครูมาคุยได้เลยนะครับ ยินดีเสมอครับ 🙏

ข้อความทุกใบต้องเป็น template ที่มีตัวแปรเสียบ ห้าม hardcode ข้อความในคอมโพเนนต์

## 8. ดีไซน์

- **มือถือเป็นหลัก** ออกแบบสำหรับคนที่เปิดใช้ระหว่างสอน มือข้างเดียว
- ปุ่มทุกปุ่มสูงไม่ต่ำกว่า 44px
- โทนอบอุ่น ดูเป็นมิตร ไม่ใช่ dashboard องค์กร · เลือกสีหลัก 1 + สีเน้น 1 + สีสถานะ (จ่ายแล้ว/ค้าง/เลยกำหนด)
- รองรับ light และ dark
- ฟอนต์ไทยที่อ่านง่ายบนมือถือ เช่น Anuphan หรือ IBM Plex Sans Thai — ตั้ง line-height ให้พอดีกับสระบนสระล่าง
- ทุกหน้าต้องมี empty state ที่บอกว่าให้ทำอะไรต่อ ไม่ใช่หน้าว่าง ๆ
- ทุก action ที่เปลี่ยนข้อมูลต้องมี toast ยืนยัน และ undo ได้ถ้าเป็นการยืนยันคาบ

## 9. ข้อมูลตัวอย่าง

ใส่ข้อมูลจำลองมาให้เลย เพื่อเปิดแอปแล้วเห็นภาพทันที: ผู้ใช้ 1 คน · ผู้เรียน 12 คน คละทั้ง 3 วิธีเก็บเงิน · คาบเรียนย้อนหลัง 2 เดือนและล่วงหน้า 2 สัปดาห์ · มีบิลที่จ่ายแล้ว บิลค้าง และบิลเลยกำหนดอย่างละอย่างน้อย 1 ใบ · มีคนที่แพ็กใกล้หมด 1 คน

มีปุ่มรีเซ็ตข้อมูลเดโมกลับค่าเริ่มต้น

## 11. เกณฑ์ว่าสำเร็จ

เดินได้ครบเส้นทางนี้บนมือถือโดยไม่ติดขัด:

**เปิดแอป → เห็นคาบวันนี้ → แตะยืนยัน 1 คาบ → ไปหน้าบิล → กดปิดเดือน → ระบบสร้างบิลและร่างข้อความ → ไปหน้าแอดมิน → กดส่ง → LINE เด้งพร้อมข้อความ → กลับมายืนยันว่าส่งแล้ว → แนบสลิป → ระบบออกใบเสร็จและร่างข้อความใบเสร็จ → ส่ง**

ตัวเลขในบิลต้องตรงกับจำนวนครั้งที่ยืนยันจริงเสมอ
