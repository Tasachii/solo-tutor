## 1 · โปรเจกต์คืออะไร

**Solo Tutor** — แอดมินส่วนตัวของติวเตอร์ ช่วยงานหลังบ้านให้ติวเตอร์ที่สอนเองคนเดียว
ครูแตะยืนยันว่าสอนเสร็จ → ระบบนับครั้ง คิดเงิน ร่างบิลและข้อความให้ → **ครูกดส่งเองใน LINE** → ผู้ปกครองเปิดลิงก์ดูบิลพร้อม QR ได้โดยไม่ต้องโหลดแอปหรือสมัครอะไร → ครูตรวจสลิป ออกใบเสร็จ

**หลักการที่ห้ามเปลี่ยน**
- AI ร่าง มนุษย์กดส่ง — ไม่มีข้อความไหนส่งออกโดยครูไม่เห็นก่อน
- **ระบบไม่ถือเงินของใคร** เงินโอนเข้าบัญชีครูตรง ทำให้ไม่เข้าข่ายต้องขอใบอนุญาตตาม พ.ร.บ.ระบบการชำระเงิน 2560
- ผู้ปกครองไม่ต้องโหลดอะไรเลย — นี่คือ insight จากการสัมภาษณ์ และเป็นจุดที่คู่แข่งที่บังคับให้ปลายทางลงแอปแพ้

**ชื่อ** — `Solo Tutor` เท่านั้น คำว่า "Solo" โดด ๆ ห้ามโผล่ใน UI (มี e2e test บังคับที่ `tests/e2e/menu.spec.ts`)

## 2 · ลูกค้าเป้าหมาย + ข้อมูลจริงที่มี

**เป้าหมาย: ติวเตอร์ที่มีนักเรียน 11–50 คน และยังไม่มีแอดมิน**

### แบบสอบถาม n=50 (ของทีมเอง)
| ข้อมูล | ตัวเลข |
|---|---|
| pain และความยอมจ่ายสูงสุดอยู่ที่ | **11–30 คน** — 76% เจอคนจ่ายช้า · 71% รับราคา 299 |
| กลุ่ม 1–10 คน | 43% ตอบว่า **ไม่สนใจ** — ไม่ใช่ลูกค้า |
| เจอผู้ปกครองโอนช้าในเดือนล่าสุด (ทั้งกลุ่ม) | 54% |
| รู้สึกบวกกับคอนเซปต์ | 80% |
| มองว่า 299 สมเหตุสมผลหรือถูก | 56% |
| **ฟีเจอร์ที่โหวตอันดับ 1** | **ส่งบิลเข้า LINE พร้อม QR — 14 เสียง** |
| ทวงคนค้างแทน | 6 เสียง (เกือบท้าย) |
| เซอร์ไพรส์อันดับ 2 | สรุปความคืบหน้านักเรียน |
| สถานะผู้ตอบ | นักศึกษา 22 · จบแล้ว 22 · ที่เหลือสอนเป็นรายได้เสริม |

### สัมภาษณ์เชิงลึก 8 คน
- 2–13 นักเรียน → ไม่รู้สึกว่าจำเป็น ยอมจ่าย 200–300 อย่างมาก
- 194 นักเรียน → จ้างแอดมินคนจริงอยู่แล้ว ยอมจ่าย 300–500
- **สิ่งที่พูดขึ้นมาเองซ้ำ ๆ โดยไม่ได้ถาม: การจัดตาราง/เลื่อนคลาส** ← สัญญาณที่แรงที่สุดที่มี
- ผู้ปกครองพาเข้าแอปหรือลิงก์ยาก — บิลต้องเป็นข้อความ LINE ธรรมดา + QR
- ครูกลัวการทวงเงินด้วยตัวเอง → รับได้กับการให้ระบบร่างให้
- "ระบบขุนทอง" ถูกพูดถึง 2 ครั้งในฐานะภาพที่นึกออก

**ข้อสรุป**: สมมติฐานผ่านแบบมีการปรับ — pain จริง แต่กลุ่มเป้าหมายไม่ใช่ 30+ อย่างที่คิดตอนแรก และสิ่งที่ครูอยากได้คือ **ออกบิล** ไม่ใช่ **ทวงหนี้**

## 3 · โมเดลธุรกิจ (สถานะปัจจุบัน)

### ราคา
| แพ็กเกจ | ราคา | หมายเหตุ |
|---|---|---|
| Free | 0 | **จำกัด 5 นักเรียน** (ตัดสินใจแล้ว — ยังไม่ได้ทำในโค้ด) |
| Pro รายเดือน | 299 บาท/เดือน | subscription ปกติ ครูกดยกเลิกเองได้ ไม่ใช่คิดตามจำนวนบิล |
| Pro 3 เดือน | 799 บาท | เฉลี่ย 266/เดือน |
| Pro 12 เดือน | 2,490 บาท | เฉลี่ย 208/เดือน ประหยัด 1,098 |

**ยกเลิกไปแล้ว: Concierge 1,500** — แพงเกินและไม่มีใครในกลุ่มเป้าหมายจ่าย

### ต้นทุนต่อลูกค้าต่อเดือน
| รายการ | บาท |
|---|---|
| ตรวจสลิป (API) | 10–15 |
| AI ร่างข้อความ | 5–15 |
| เซิร์ฟเวอร์ | 3–5 |
| ค่าธรรมเนียมรับเงิน | 0–12 |
| **รวม** | **20–45** — gross margin 85–93% |

ราคา API ตรวจสลิปที่สำรวจไว้: Thunder 0.14–0.248 ฿/สลิป · EasySlip 0.28–0.35 · SlipOK 0.36–0.42
**ต้องใช้ API จริง ไม่ใช่ OCR เอง** — OCR อ่านสลิปปลอมไม่ออก

### จุดคุ้มทุน 3 ระดับ (ต้องตอบแบบนี้ ไม่ใช่เลขเดียว)
- คุ้มค่าระบบ (server + API) ≈ **10 คน**
- เลี้ยงทีม 5 คนแบบมีเงินเดือน ≈ **450 คน**
- ระดับที่นักลงทุนสนใจ ≈ **หลักหมื่นคน**

### คู่แข่งตัวจริง
Fastwork (หาลูกค้า ไม่ใช่จัดการลูกค้า) · **ป้ามวล** · Protutor / BestKru (จับคู่ครู-นักเรียน) · ระบบขุนทอง (ทวงหนี้) · **Excel + LINE (คู่แข่งที่แท้จริง)**

### Unfair advantage — สถานะจริง
มีจริง 1 ข้อครึ่ง จาก 7: **ข้อมูลวงในบางส่วน** (แบบสอบถามที่เก็บเอง) + **ลูกค้าที่กำลังจะมี**
ที่ไม่มี: expert endorsement · dream team · personal authority · network effects · community
สิ่งที่มีจริงและมักเรียกผิดเป็น network effect: **distribution loop** (ชื่อติดไปกับทุกบิล) และ **switching cost** (ประวัติคาบเรียนย้อนหลังย้ายไม่ได้)
ในกรอบ 7 Powers เราแข็งสองข้อ: **Counter-Positioning** (ไม่บังคับผู้ปกครองลงแอป) และ **Switching Costs**
รายละเอียดเต็มอยู่ที่ `docs/unfair-advantage.md`

### สิ่งที่ตัดสินใจ "ยังไม่ทำ"
- **LINE OA / Messaging API** — ยังไม่ต่อ ใช้ share link ไปก่อนจนกว่าผู้ใช้จ่ายเงินจริงจะบอกว่าการ paste เป็นปัญหา (แผนเต็มเขียนไว้แล้วที่ `docs/line-oa-plan.md` ถ้าจะทำ)
- **โหมดผู้ปกครองแยก** — ไม่ทำ ผู้ปกครองใช้ลิงก์พอ
- **backend จริง** — ยังไม่ทำ แต่โค้ดเตรียม repository pattern แบบ async ไว้แล้วเผื่อสลับ (แผนเลือก Supabase)

## 5 · ต้องแก้อะไรต่อ — จากรีวิวเว็บที่ deploy อยู่จริง

### กำลังแก้อยู่ ยังไม่ commit
- `src/copy/index.ts` — การ์ดตัวอย่างบนหน้าแรกเปลี่ยนจากเคสตัดผม/ต่อเล็บ/ทำความสะอาด เป็นเคสติวเตอร์ล้วนแล้ว **แต่ยังไม่ push** ของที่คนเห็นบนเว็บตอนนี้ยังเป็นเคสเก่า

### ต้องแก้ก่อนขึ้นเวที
| # | ปัญหา | ที่ไหน |
|---|---|---|
| 1 | **วันที่ทั้งแอปเป็นปีที่แล้ว** — หน้าวันนี้ขึ้น "2 กันยายน 2568" หน้าบิล "กันยายน 2568" ข้อความ "ส.ค. 2568" · demo data ผูกกับวันที่ตายตัว 2 ก.ย. 2025 ต้องทำให้เลื่อนตามวันจริง | `src/mock/` |

### ควรแก้ถ้ามีเวลา
| # | ปัญหา |

| 8 | QR ยังเป็นตารางหมากรุกพร้อมข้อความ "ใช้ชำระเงินจริงไม่ได้" — ถ้า demo ด้วยบัญชีครูจริง ควรเป็น QR PromptPay จริง |

### เรื่องการโชว์ ไม่ใช่บั๊ก
แอปเป็น mobile-first พอฉายจอกว้างจะเหลือที่ว่างครึ่งจอและแถบเมนูลอยกลาง — ตอน demo ให้ย่อหน้าต่างเป็นความกว้างมือถือ

### งานหลังการแข่ง (ไม่ต้องทำตอนนี้)
ต่อ API ตรวจสลิปจริง · ระบบจัดตาราง/เลื่อนคลาส (สิ่งที่ครูขอเองซ้ำสุด) · สรุปความคืบหน้านักเรียน · backend Supabase + RLS · ระบบเก็บเงิน subscription จริง · LINE OA ถ้าผู้ใช้จ่ายเงินบอกว่าจำเป็น

## 8 · Feedback ที่ยังต้องตอบให้ได้

### กรรมการ 4 คน พูดตรงกัน 5 เรื่อง
1. เริ่มจาก niche ก่อน mass
2. ต้องมีตัวเลขตลาดจริง TAM/SAM/SOM
3. ยังไม่ได้ทำการบ้านเรื่องคู่แข่ง
4. ของฟรีเป็นความเสี่ยง — ลูกค้าอาจใช้ฟรีตลอด หรือทำเองด้วย AI
5. ฟีเจอร์ลอกง่าย ต้องหาสิ่งที่ลอกไม่ได้

**คำถามที่รอบที่แล้วตอบไม่ได้และต้องตอบให้ได้รอบนี้: "มีติวเตอร์ใช้แล้วกี่คน"** (พี่โป)

### Mentor พี่ TPJ + Ing (6 ก.ย.)
- **ทำ tutor อย่างเดียว โฟกัสอย่างเดียวให้มีรายได้จริง** แล้วค่อยบอกว่าจะเอาโมเดลที่สำเร็จไปใช้ต่อ — เป็นประโยคปิดประโยคเดียว ไม่ใช่เนื้อหาในพิทช์
- **วิจัย 5 อย่างที่ติวเตอร์ยอมจ่าย** — ระบบบิล · ระบบจัดตาราง · ทำคอร์ส/สื่อการสอนให้ · หานักเรียนให้ · studio ให้เช่า → เลือกอันเดียวที่ทำเงินได้จริง (Punch + Ing ส่งพุธ 9 ก.ย.)
- **พิทช์เป็นสตอรี่ครูจริงหนึ่งคน** ตั้งแต่ต้นจนจบ ถ้าได้ให้ครูจริงพูดเอง หรืออัดคลิป 20 วินาที
- **BMC ห้ามฉายขึ้นจอ** — เป็นเอกสารแนบไว้ตอบตอน Q&A เท่านั้น

### วิธีวิจัย 5 อย่างที่ให้คำตอบจริง
ห้ามถาม "สนใจไหม" · ให้ครู 15 คน**เรียงลำดับ** · ถามต่อว่าราคาเท่าไหร่จะจ่าย แล้วดันราคาขึ้นจนปฏิเสธ · ถามย้อนหลังว่า **"ปีที่แล้วจ่ายเงินให้อะไรเกี่ยวกับการสอนบ้าง เท่าไหร่"** · ถ้ามีอันไหนชนะชัด ให้ **ลองขายก่อนสร้าง** เก็บมัดจำ 100 บาท ใครโอนคือคำตอบจริง

## 9 · การวัดขนาดตลาด (วิธีที่ตกลงกันไว้ ห้ามหยิบเลขจากบทความ)

นับจากล่างขึ้นบนแล้วโชว์สูตร:
1. นับติวเตอร์ที่มีตัวตนออนไลน์ — รายชื่อบน Protutor + BestKru + สมาชิกกลุ่ม Facebook/LINE รับสอนพิเศษ 5 กลุ่มใหญ่สุด (ตัวเลขที่กดดูได้)
2. คูณสัดส่วนที่มีนักเรียน 11–50 คน จากแบบสอบถามของเราเอง **และบอกตรง ๆ ว่ามาจาก n=50**
3. คูณ 299 × 12 = SAM ต่อปี
4. SOM = จำนวนที่เข้าถึงได้จริงใน 12 เดือนแรกจากช่องทางที่มีตอนนี้

แหล่งราชการที่ควรลอง: สำนักงานสถิติแห่งชาติ (แรงงานนอกระบบ) · กรมพัฒนาธุรกิจการค้า (โรงเรียนกวดวิชาจดทะเบียน) · สช. (โรงเรียนนอกระบบ)

## 11 · มติที่ห้ามย้อน (ถ้าจะย้อนต้องมีเหตุผลใหม่)

1. ชื่อคือ **Solo Tutor** เท่านั้น ไม่มีชื่อย่อยรายอาชีพ คำว่า Solo โดด ๆ ห้ามโผล่
2. **โฟกัสติวเตอร์อย่างเดียว** อาชีพอื่นเป็นประโยคปิด ไม่ใช่เนื้อหาพิทช์
3. ขายว่า **"ออกบิลและจัดการเงิน"** ไม่ใช่ "ทวงเงินแทนครู" — ข้อมูลของเราเองบอกแบบนี้
4. **ระบบไม่ถือเงิน** เงินเข้าบัญชีครูตรง
5. **ไม่หัก % จากค่าเรียน** เก็บเป็น subscription เท่านั้น
6. ราคาเดียว 299 + แพ็ก 3/12 เดือน · ไม่มี Concierge · ครูกดยกเลิกเอง
7. Free จำกัด 5 นักเรียน
8. ยังไม่ต่อ LINE OA
9. BMC ไม่ฉายขึ้นจอ
10. ทุกตัวเลขที่พูดต้องบอกที่มาในประโยคเดียวกัน
