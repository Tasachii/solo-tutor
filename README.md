# Solo Tutor

แอดมินแบบ local-first สำหรับติวเตอร์ที่รับงานเอง เก็บเงินเอง และตอบแชทเอง
เดโมเป็น static app ข้อมูลอยู่ในเบราว์เซอร์ ไม่มีบัญชีผู้ใช้หรือ cloud sync และไม่รับชำระเงินแทนผู้ให้บริการ

เดโม: https://tasachii.github.io/solo-tutor/

---

## หลักการที่ห้ามละเมิด

1. **Solo ไม่ถือเงินของใคร** — แสดงช่องทาง PromptPay ของผู้ให้บริการ ผู้ใช้ตรวจยอดจากสลิปเอง แล้วออกใบเสร็จเมื่อยอดครบ เงินเข้าบัญชีเจ้าของงานโดยตรง
2. **ตัวเลขทุกตัวมาจาก ledger** — ไม่มีค่าคงที่ ไม่มีเทมเพลตหรือ AI คำนวณเงินเอง
3. **กฎร่างข้อความ คนกดส่ง** — ไม่มีข้อความไหนออกไปโดยผู้ใช้ไม่ได้กดปุ่ม "ส่ง"
4. **ข้อความการเงินแยกตามอาชีพ** — core ใช้ template/vocab จาก `professions/` และ `copy/`; หน้าจอปัจจุบันรองรับติวเตอร์เป็นหลัก
5. **ข้อความถึงลูกค้าเป็นเสียงของผู้ให้บริการ** — ห้ามมีคำว่า "ระบบ" "อัตโนมัติ" หรือ "Solo" (ยกเว้นบรรทัดเล็กท้ายใบเสร็จ)

## โครงสร้าง

```
src/
  core/         engine — ledger, billing, messages, faq, selectors, export
                คำนวณและตรวจความถูกต้องของข้อมูล; React state อยู่ใน store.tsx
  app/          จอของผู้ให้บริการ + จอฝั่งลูกค้า (ClientPreview, Receipt)
  platform/     หน้าขาย — Landing, Pricing, WaitlistSheet
  professions/  นิยามอาชีพ: vocab, การคิดเงิน, กฎ FAQ
  copy/         ข้อความร่วมและเทมเพลตของติวเตอร์
  mock/         seed สำหรับชุดข้อมูลเดโม
```

### เพิ่มอาชีพใหม่

เพิ่มนิยามและข้อความใน `src/professions/`:

1. สร้าง `src/professions/<id>.ts` ที่ export `ProfessionTemplate`
2. ใส่ในลิสต์ใน `src/professions/index.ts`

กำหนด `templates`/`modeLabels` หรือใช้ generic fallback และทดสอบ contract ของข้อความ
ก่อนเปิดใช้อาชีพใหม่ ต้องตรวจ onboarding, ฟิลด์บริการ และ UX ทั้งเส้นทางด้วย ปัจจุบันเปิดใช้งานติวเตอร์เท่านั้น

## รัน

```bash
npm install
npm run dev
```

| คำสั่ง | ทำอะไร |
| --- | --- |
| `npm run dev` | เซิร์ฟเวอร์สำหรับพัฒนา |
| `npm run build` | `tsc` แล้ว build ลง `dist/` |
| `npm run preview` | เสิร์ฟ `dist/` ที่ build แล้ว |

### พารามิเตอร์สำหรับเดโม

อยู่ใน hash ได้ (HashRouter) หรือใน query ปกติก็ได้:

- `?scenario=package-heavy` — เลือกชุดข้อมูล: `default`, `package-heavy`, `monthly-heavy`, `empty`

## หมายเหตุทางเทคนิค

- **HashRouter** เพราะ GitHub Pages ไม่มี SPA fallback
- **วันที่** เก็บเป็น ISO ค.ศ. แสดงผลเป็น พ.ศ. คำนวณด้วย `Date.UTC` ทั้งหมดจึงไม่ผูกกับ timezone
- **สถานะ** เก็บใน `localStorage` คีย์ `solo-demo-v3` · schema 4 มี migration จาก 3 ที่ไม่ทำข้อมูลหาย
- **โฉม Navy** (6 ก.ย. 2569) — ธีมมืดเป็นค่าเริ่มต้น สีหลัก `sky` (ฟ้าเพอริวิงเคิล) · token ใหม่ `--brand-2` `--glow` `--glow-a/b` `--radius-lg` · ไอคอนเส้นชุดเดียว (`Icon`) แทนอีโมจิในแท็บ · ภาพเงาสีเดียว (`Silhouette`) ต้นฉบับของเรา · ธีมสว่างและสีหลักอีก 5 สีเลือกได้จากเมนู · ยังไม่มีสีดิบนอก `index.css`
- **สำรองลง Google Sheets** เมนู → ชีตอยู่ใน Drive ของครูเอง เขียนอย่างเดียว (4 แท็บอ่านง่าย + แท็บซ่อนเก็บ JSON ไว้กู้คืน) · แหล่งความจริงยังเป็นเครื่อง · ตั้งค่าตาม `docs/google-sheets/README.md`
- **นำเข้า/ส่งออกรายชื่อ** เมนู → อ่าน `.xlsx` `.csv` `.tsv` หรือวางจากชีตได้ · ตัวอ่าน xlsx เขียนเอง (zip + XML ผ่าน `DecompressionStream`) ไม่มี dependency
- **หน้าเลือกรูปแบบการเก็บเงิน** (`#/start`) ทางเข้าจาก Landing/ราคาทุกปุ่ม — รายครั้ง · เหมารายเดือน · แพ็ก/คอร์ส · ผสม แตะเดียวเข้าแอป เดโมสลับชุดข้อมูลให้ตรงแบบ โหมดใช้จริงเปลี่ยนแค่ค่าเริ่มต้น+ตัวกรอง ไม่แตะข้อมูล เปลี่ยนทีหลังได้ที่เมนู → รูปแบบการเก็บเงิน · คำในหน้านี้เติมจาก vocab ของอาชีพ (`fillVocab`) ไม่ผูกกับครู
- **โหมดใช้จริง** เมนู → เริ่มใช้จริง = ล้างข้อมูลสมมติ เดินวันตามเครื่อง ตรวจสลิปเองไม่สุ่ม
- **ชื่อและบัญชีรับเงิน** (โหมดใช้จริง) เมนู → แก้ชื่อ พร้อมเพย์ และคำลงท้าย ครับ/ค่ะ ได้ทุกเมื่อ ร่างที่รอส่งจะถูกเขียนใหม่ตาม — ข้อความถึงลูกค้าทุกประโยคใช้ `{p}`/`{pq}` แทนคำลงท้าย ห้ามฝัง ครับ/ค่ะ ตายตัว
- **สำรองข้อมูล** เมนู → สำรองข้อมูล ได้ไฟล์ JSON กู้คืนได้ · เตือนเมื่อทิ้งช่วงเกิน 7 วัน
- **ขนาดจอ** เมนู → ขนาดจอ · `จอฉาย` ขยายทั้งตัวอักษรและความกว้างสำหรับฉายตอนพรีเซนต์
- **เอกสารข้ามเครื่อง** โหมดจริงใช้สำเนาข้อมูลใน hash URL เฉพาะผู้รับ/เอกสารนั้น เปิดได้โดยไม่ต้องมี localStorage ของผู้ส่ง มีวันที่กำกับ ไม่อัปเดตอัตโนมัติ ไม่ลงลายเซ็น และเพิกถอนลิงก์ไม่ได้ ผู้ที่ได้รับลิงก์อ่านข้อมูลได้ ควรตรวจผู้รับก่อนส่ง
- **การบันทึก** บันทึก action ลง localStorage ก่อนเปลี่ยน UI; quota/permission error ไม่ยืนยันการเปลี่ยนแปลง ข้อมูลเสียเก็บไว้ให้ดาวน์โหลด และเก็บสำเนาก่อน restore ที่ `solo-demo-v3-before-restore`
- **รับเงินหลายงวด** ยอดค้างใช้ `balanceDue`; ใบเสร็จสรุปเต็มบิลออกเมื่อรับครบ รายการจ่ายแต่ละงวดยังคงเดิม
- **หน้าแรก / เข้าสู่ระบบ** (8 ก.ย. 2569 ค่ำ) กฎเข้าแอปอยู่ใน `core/entry.ts` (standalone หรือโหมดจริงที่ onboarded แล้ว → `/app/today`, `?stay=1` = ดูหน้าขาย) · หน้า `/login` ห่อ `CloudSyncProvider` เพื่อรอผลดึงคลาวด์ก่อนพาเข้าแอป · ฟอร์มสมัคร/เข้าสู่ระบบเป็น `AuthForm` ตัวเดียวกับหน้าบัญชีครูและ LINE
- **แท็บค้างจ่าย / การบ้าน** (8 ก.ย. 2569) หน้าแอดมิน → `core/collections.ts` รวมบิลค้าง+ขั้นทวง+ประวัติทวง · `core/homework.ts` ledger การบ้าน (`AppState.homework` เป็น array เสริม ไฟล์เก่าเปิดได้) ร่างทวงการบ้าน derive เมื่อเลยกำหนด · ข้อความชนิดใหม่ `nudge` `homework` `homework_reminder` · การส่งผ่าน LINE OA ใช้ `app/oaSend.ts` ชุดเดียวกันทั้งการ์ดเดี่ยวและส่งเป็นชุด
- **ส่งข้อความ** ผ่าน LINE share link ออกจากบัญชีของผู้ใช้เอง ไม่ใช่บอท และนับว่าส่งเมื่อผู้ใช้ยืนยัน
- **สี** อยู่ใน CSS custom properties ที่หัวไฟล์ `src/index.css` เท่านั้น มีธีมสว่าง/มืด/ตามเครื่อง
- **CSV** ใส่ BOM ให้ Excel ไทยอ่านออก และเรียงตามวันที่จริงไม่ใช่สตริงที่ format แล้ว
- **ไม่มี UI library** ใช้ CSS ล้วน dependency มีแค่ `react`, `react-dom`, `react-router-dom`

## ฟอร์มลงชื่อ

`WAITLIST_ENDPOINT` ใน `src/platform/config.ts` ว่างไว้ = ข้อมูลเก็บเฉพาะใน `localStorage` ของเบราว์เซอร์นี้
ไม่ถูกส่งออกไปไหน ใส่ URL ของ Google Form `formResponse` และแก้ `WAITLIST_FIELDS`
ให้ตรงกับ entry id จริงเมื่อพร้อมเก็บข้อมูล
